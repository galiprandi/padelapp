## 🧠 APRENDIZAJES
## 2026-08-16 - Instant Profile Auto-Save & Onboarding Navigation Guard
**Learning:** In auto-saving forms where user actions trigger asynchronous server actions during onboarding transitions, executing client router navigation (`router.push('/me')`) synchronously before the async mutation resolves risks dropping pending alias changes or throwing unhandled unmount errors. Returning a `Promise<boolean>` from the save handler and awaiting its completion before routing guarantees data persistence. Additionally, reading client storage (e.g., `localStorage`) directly inside lazy `useState` initializers prevents cascading synchronous `setState` re-renders in `useEffect`.
**Action:** Always return a Promise from auto-save handlers so navigation actions can await completion before transitioning, and use lazy `useState` initializers when initializing state from `localStorage`.

## 2026-08-15 - H1 Header MDS Standardization on Login & Install Pages
**Learning:** According to MDS §1.8, flat headers (`<h1>` and `<p>`) must adhere to clean typography rules without non-standard letter-spacing adjustments like `tracking-tight` or `uppercase` unless explicitly specified. Standardizing page titles across authentication and entry pages like `/login` and `/install` ensures consistent visual hierarchy and typographic harmony across the entire mobile application shell.
**Action:** Always check `<h1>` element classes during UI audits to confirm they avoid unnecessary `tracking-*` or `uppercase` utility classes.

## 2026-08-14 - Mini-Court Court Side Position Indicator
**Learning:** Visual indicators that mirror real-world sports contexts (such as a miniature padel court diagram highlighting left/Revés vs right/Derecha sides) provide instantaneous cognitive recognition for competitive players without cluttering the screen. By marking graphic sub-elements with `aria-hidden="true"` and relying on surrounding descriptive semantic text (`networkStats.preferredSide`), the UI satisfies both high visual fidelity and WCAG/MDS accessibility requirements.
**Action:** Use clean, minimal SVG/CSS sub-diagrams when representing tactical or spatial preferences (like court side), keeping decorative shapes hidden from screen readers.

## 2026-08-13 - Public Profile Accessibility & High-Fidelity Mocking under Bypass
**Learning:** Adding screen-reader accessibility metadata (`aria-label`) that translates visual indicator patterns (such as green and red dots representing wins and losses) into localized text (e.g., `'Forma reciente: G, P'`) is crucial for compliance with modern accessibility standards like WCAG and the Minimal Design System (§2.9). By pairing this with `aria-hidden="true"` on the visual sub-indicators, we avoid screen-reader noise while preserving the full visual context. Furthermore, when implementing mock fallback layers for local/bypass modes, casting mock objects to the exact TypeScript return type using `Awaited<ReturnType<typeof privateDbHelper>>` prevents dynamic parameter loss and eliminates implicit `any` parameter compilation warnings at the page consumption sites.
**Action:** Always provide explicit, translated screen-reader metadata for icon grids or visual status matrices, and always type-cast mock bypass payloads to their exact database-helper return type instead of using `any`.
