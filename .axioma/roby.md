## 🧠 APRENDIZAJES
## 2026-08-13 - Public Profile Accessibility & High-Fidelity Mocking under Bypass
**Learning:** Adding screen-reader accessibility metadata (`aria-label`) that translates visual indicator patterns (such as green and red dots representing wins and losses) into localized text (e.g., `'Forma reciente: G, P'`) is crucial for compliance with modern accessibility standards like WCAG and the Minimal Design System (§2.9). By pairing this with `aria-hidden="true"` on the visual sub-indicators, we avoid screen-reader noise while preserving the full visual context. Furthermore, when implementing mock fallback layers for local/bypass modes, casting mock objects to the exact TypeScript return type using `Awaited<ReturnType<typeof privateDbHelper>>` prevents dynamic parameter loss and eliminates implicit `any` parameter compilation warnings at the page consumption sites.
**Action:** Always provide explicit, translated screen-reader metadata for icon grids or visual status matrices, and always type-cast mock bypass payloads to their exact database-helper return type instead of using `any`.

## 2026-08-10 - Public Profile Header & Onboarding Banner MDS Standardization
**Learning:** The Minimal Design System (MDS) guidelines are critical for visual consistency, clarity, and performance. Specifically, avoiding translucent background elements on content panels (MDS §1.3) prevents low-contrast text render paths, and standardizing typography (MDS §1.8) maintains clean spacing across the mobile-first UI. Polishing layout cards to use solid backgrounds (`bg-card`, `bg-muted`) and removing arbitrary uppercase/tracking styling ensures that guest users on public profile pages receive a high-fidelity visual experience.
**Action:** Always verify custom alert callouts and headers against the design maxims of DESIGN.md, and replace translucent properties with MDS solid class alternatives.

## 2026-08-09 - Profile Alias Validation, Spanish Localization & State Synchronization
**Learning:** During auto-save inputs on forms, any backend transformation (like `capitalizeName` returning `El Muro` from `el muro`) can create visual inconsistencies on the frontend if the local state is not immediately synchronized with the sanitized response returned by the server. Updating the local React state with the server-formatted string on Promise resolution guarantees immediate, seamless consistency without requiring page refreshes. Additionally, server-side messages must strictly follow Argentine Spanish (voseo) language guidelines for UX branding consistency.
**Action:** Always sync client state with the server-returned payload on successful updates of input fields, and ensure backend actions output localized, brand-consistent errors.
